## Context

ProjectServiceImpl.loadProjectWorkflows делает Mono.empty для любой ошибки. BoardServiceImpl в gateway уже различает NOT_FOUND и остальные статусы. В TAS-533 допустимы общий отказ контекста либо новое поле workflowsUnavailable; выбираем первый вариант с минимальной совместимой областью.

## Decisions

- Возвращать Mono.empty только для gRPC NOT_FOUND; остальные ошибки передавать без подмены статуса и подробностей.
- Ошибка любого типа завершает чтение контекста ошибкой, даже если другой workflow уже прочитан.
- Сохранить отсутствие записей/аудита/outbox при чтении, метаданные типов и обычный успешный контекст.
- Вложенный workflow→project запрос метаданных сохраняет requestId исходного verified context через RpcContextBridge.outboundHeader: E2E выявил, что новый случайный идентификатор отклонялся защитой RPC ещё до обычного ответа NOT_FOUND.
- Проверить частичный отказ для PERMISSION_DENIED, UNAVAILABLE, DEADLINE_EXCEEDED, INTERNAL, FAILED_PRECONDITION, полный отказ и оба варианта NOT_FOUND. Выполнить затронутые project-service checks и HTTP/RPC проверку маппинга ошибок.

## Risks / Trade-offs

Отказ workflow одного типа теперь делает весь контекст недоступным. Это явно разрешённая цена варианта 1 в задаче; частичное отображение требует отдельного согласованного контрактного изменения. Данные проекта не изменяются.

## Open Questions

Нет: оба варианта разрешены постановкой, выбран вариант без изменения публичного контракта.
