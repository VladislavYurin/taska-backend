# Spec Delta

## Purpose
Подтверждённо удалять проект без корзины и освобождать его квоты после фактической очистки, сохраняя изоляцию компаний и повторяемость операции.

## ADDED Requirements

### Requirement: Подтверждённое принятие удаления
Система SHALL принимать отдельную команду удаления с текущим tenant/project ACL, capability project.delete, If-Match, Idempotency-Key и подтверждением project key. Некорректные запросы MUST сохранять исходное состояние.

#### Scenario: Разрешённое удаление
- **WHEN** разрешённый администратор подтверждает ключ своего проекта и текущую версию
- **THEN** возвращается 202 Operation типа PROJECT_DELETE с resourceId, а новые изменения проекта закрываются

#### Scenario: Отказ без побочных эффектов
- **WHEN** проект чужой, роль недостаточна, версия устарела или подтверждение неверно
- **THEN** сервер отвечает скрытым 404, 403, 412 либо 422 и не создаёт операцию или эффекты квот

### Requirement: Повторяемое завершение
Система SHALL сохранять actor-bound результат запроса, сериализовать конкурирующие команды и возобновлять принятую очистку после сбоя. Неизвестный результат MUST сохранять занятую квоту.

#### Scenario: Повтор и сбой
- **WHEN** потерян ответ либо перезапущен worker после частичной очистки
- **THEN** тот же запрос возвращает ту же операцию, очистка продолжается, каждый release применяется однократно

#### Scenario: Другой ключ
- **WHEN** для удаляемого проекта поступает новая команда с другим ключом
- **THEN** возвращается конфликт без второй операции

#### Scenario: Истёкший manifest без подтверждения очистки
- **WHEN** отмена upload сохранила EXPIRED, но S3 purge или подтверждение root ещё не завершились
- **THEN** PROJECT usage и reservation сохраняются, а повтор продолжает очистку без ложного ACK

#### Scenario: Большой проект
- **WHEN** содержимое требует нескольких порций SQL-очистки
- **THEN** незавершённая операция удерживает PROJECT usage, а lifetime retirement фиксируется только с завершением последней порции

### Requirement: Сохранение границ и квот
Система SHALL удалять только данные и объекты конкретного tenant/project; общие templates, другие проекты и глобальный аватар сохраняются. Архивирование MUST сохранять usage; завершённое удаление MUST сохранять lifetime tombstone старого UUID.

#### Scenario: Очистка A
- **WHEN** удаление проекта A завершается
- **THEN** его содержимое недоступно, project/storage usage освобождены, места и проект B не изменены

#### Scenario: Новый проект
- **WHEN** после освобождения квоты создаётся проект с новым UUID
- **THEN** его lifetime usage начинается с нуля, а позднее событие старого UUID не восстанавливает старый проект
