# Пауза владельцем и блокировка платформой

TAS-480 реализует независимые причины `OWNER_PAUSE` и `PLATFORM_BLOCK` в `tenant_restrictions`. У каждой причины свой source_id и версия; остальные источники (`NONPAYMENT`, `QUOTA_EXCEEDED`, `FINANCIAL_DISPUTE`) сохраняются независимо. Оплата и снятие одной причины не удаляют другие. Private administrative reason хранится только в append-only audit, публичные DTO/события содержат код причины.

Команды REST: `PUT /api/v1/tenants/{tenantId}/pause` с `{confirmed:true}`, `DELETE` того же пути без body, `PUT /api/v1/admin/tenants/{tenantId}/platform-block` с `{enabled,reason,confirmed}`. RPC: `TenantService.PauseTenant/ResumeTenant`, `PlatformService.SetPlatformBlock`; authoritative sources — [tenant proto](../grpc-common-lib/src/main/proto/v1/tenant-registry.proto), [platform proto](../grpc-common-lib/src/main/proto/v1/platform-flags.proto), [OpenAPI](../api-gateway/src/main/resources/static/openapi.yml).

Все команды требуют canonical UUID `Idempotency-Key` и strong quoted tenant version в `If-Match`. Missing version даёт 428, stale — 412, конфликт payload под прежним ключом — 409. Tenant lock сериализует команды с rename/membership/lifecycle; причина, parent versions, audit, outbox и frozen receipt фиксируются одной транзакцией. Повтор сначала проверяет текущую identity/owner/admin, затем возвращает сохранённый ответ, не повторяя эффект. Новый ключ с актуальной версией для уже достигнутого состояния не увеличивает версии и не создаёт события.

Обычный owner управляет своей паузой при актуальном ACTIVE membership. TENANT_ADMIN без владения не получает это право. Platform block требует подтверждённую administrative authority: текущий GLOBAL_ADMIN с web MFA либо подходящий administrative credential/grant/target. Административный путь аудитируется и не выдаётся из одной строки роли. DELETING/DELETED не допускают новый lifecycle change. Флаг OWNER_PAUSE применяется только к новой установке; его выключение не мешает снять существующую паузу или получить разрешённый replay.

Действующая матрица OWNER_CONTROL запрещает новую owner-команду при platform block/dispute. Предложение фронта изменить resume под блокировкой и уточнить directory/inbox scope вынесено в [TAS-535](https://jira.ozero.dev/browse/TAS-535). До решения матрица не расширяется молча. Существующие metadata, lifecycle и внутренний membership RPC не закрываются флагом чтения содержимого; публичный members REST adapter этой задачей не активируется.

`MembershipSnapshot`/bounded batch несут current independent restrictions и restriction_version из того же SQL snapshot. Новые ManagedDomainReads требуют согласованный положительный version и причины; старый/неполный primary response даёт UNAVAILABLE. TenantDecisionFacts и tenant capabilities объединяют root причины с коммерческим entitlement на каждом запросе. READ_WHILE_RESTRICTED по умолчанию true; false закрывает content read ordinary участников под pause/block с READ_ONLY и соответствующей причиной. Разрешённые metadata/financial capabilities остаются доступны.

`TenantPaymentState` также несёт текущие причины/version. AutopayStore требует этот primary source для нового DISPATCH и повторно проверяет его перед admission claim; pause/block/dispute не допускают новый charge. Missing/invalid/offline root закрывает admission. Accepted/UNKNOWN попытки проходят существующую reconciliation, не создавая вторую попытку. GrpcAutopayWorker предъявляет managed purpose `billing` и identity `billing-service`; deployment trust должен явно разрешать dispatch и root payment-state read для этого issuer/tenant/scopes. Не включать worker без его действующих owner/PSP/configuration adapters.

Pause/resume не вызывает billing mutation: paid period продолжает идти; resume после expiry не продлевает его и не создаёт платёж. Никаких PSP charges локальная tenant E2E не делает. Новые migrations добавлены после применённых changesets: таблицы/RLS/audit bootstrap, затем дополнительная actor-list policy и обновление list function в одной транзакции. Rollout: root schema/service с новыми snapshots прежде новых consumers; отсутствующие обязательные root поля дают безопасный отказ.

Проверки: [матрица](../docs/agents/verification.md), `TenantRegistryIntegrationTest`, `TenantCapabilitiesIntegrationTest`, `ManagedMembershipSnapshotTest`, `AutopayIntegrationTest`, `TenantRestrictionControllerTest` и owned [REST/mTLS runner](../scripts/harness/tenant_restrictions_e2e.py). Результаты/fixtures/credentials остаются в ignored target или приватном внешнем каталоге.
