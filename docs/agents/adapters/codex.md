# Адаптер Codex

Поддерживаемый entry point — корневой `AGENTS.md`, общий маршрут — [workflow guide](../workflows.md). Skills находятся в `.agents/skills`; отдельный конфигурационный файл проекта для их обнаружения не нужен. Настройка человека и подключений — [setup](../setup.md).

Адаптер не требует plugin/личного skill Taska и не устанавливает client автоматически. Его внешняя зависимость — выбранный и авторизованный Codex. Записывайте точную установленную версию в приватные результаты smoke. Официальные правила: [AGENTS discovery](https://developers.openai.com/codex/guides/agents-md), [skills](https://developers.openai.com/codex/skills).

## Два разных smoke

`python3 scripts/harness/workflows.py smoke` проверяет структуру пяти skills, их ссылки и доступность локальных команд. Он явно сообщает `clientDiscovery: NOT_VERIFIED`. Это не проверка модели/авторизации/MCP.

Для фактического discovery начните новую Codex-сессию в **чистом** checkout без прошлой истории. Попросите перечислить загруженные источники инструкций и skills, затем явно применить `$docs-sync`, прочитать его файл, выполнить `doctor --tier static`, `docs-check` и локальный smoke. Не предоставляйте агенту заранее перечень ожидаемых ответов. Проверяющий сверяет реальные tool calls, пути и outputs. Простого утверждения «инструкции прочитаны» недостаточно.

При доступном CLI команда для read-only эксперимента (сперва сверить `codex exec --help` установленной версии):

```sh
codex exec --sandbox read-only --ephemeral --ignore-user-config \
  'Перечисли загруженные проектные инструкции и repo-local skills. Используй $docs-sync для read-only проверки документации и доступности команд harness. Никаких внешних инструментов или изменений файлов. Сообщи ограничения.'
```

`--ignore-user-config` исключает пользовательский config, но не доказывает отсутствие всех глобальных правил/skills. Для строгой независимости используйте новый разрешённый профиль/контейнер без личного контекста, со своей штатной авторизацией. Не копируйте credentials в test fixture. Если установленная версия не поддерживает флаги, не заменяйте их обходом sandbox: выполните desktop smoke вручную и зафиксируйте способ.

Результаты вне Git: клиент/версия, source head, обнаруженные пути, выполненные команды/коды, глобальные источники, ограничения. Невозможность авторизации или соединения означает BLOCKED, а не успешный client smoke.

## Матрица поддержки

| Клиент | Что предоставляет repository | Что подтверждает совместимость |
|---|---|---|
| Codex CLI/desktop | AGENTS + `.agents/skills` + этот smoke | свежая сессия конкретной установленной версии |
| Claude Code | специального адаптера нет | не проверено; переносить общие инструкции вручную по правилам клиента |
| Cursor | специального адаптера нет | не проверено; наличие Markdown не является client smoke |

Не создавать фиктивные CLAUDE/Cursor entry points только ради таблицы. При добавлении клиента отдельно описать discovery, commands, scopes, версию и наблюдаемый smoke; общие процедуры сохранить в одном месте.
