# B2B: принятые технические решения

Ревизия SA-2026-11-03. Это проектные решения аналитики, принятые в пределах поручения владельца о minor decisions. Они дополняют D01–D253 и не подтверждают реализацию. Решения владельца и делегированная retention policy — [commercial-decisions.md](commercial-decisions.md) / [retention-policy.md](retention-policy.md). Реальные реквизиты продавца/merchant не подменяются defaults.

| ID | Решение | Причина / реализация |
| --- | --- | --- |
| T01 | Сервис владеет своей БД; cross-service UUID — логическая ссылка, не SQL FK | Межсервисная согласованность: transactional outbox + идемпотентные command/event consumers + reconciliation. FK внутри одной БД обязательно включает tenant там, где обе таблицы tenant-owned. |
| T02 | Новые неизменяемые entity IDs — UUID, адресация компании по UUID | Existing identifiers не перенумеровывать. API всегда проверяет принадлежность UUID. Slug/alias в первой версии не вводится; название компании не является ключом адресации. |
| T03 | Чистый старт без legacy tenant и backfill | Применённые changesets сохраняются. Добавить новые versioned changesets, очистку старых тестовых данных выполнить отдельным контролируемым manifest. Миграция не скрывает наличие небезопасных старых строк. |
| T04 | Tenant SQL: обязательный predicate + RLS + transaction-local context | Runtime DB роль без BYPASSRLS/DDL, не владелец таблиц; FORCE RLS для tenant tables. Connection executor устанавливает контекст bind-параметром в той же транзакции. Admin SQL — отдельный audited executor с явным scope, не отсутствие tenant. |
| T05 | Публичный tenant path обязан совпадать с tenant выбранной сессии/grant | Выбор другой компании — выдача независимой tenant session; refresh не меняет область. Подмена path/header не выбирает новую компанию. Admin grant проверяет явное множество/PLATFORM и уровень. |
| T06 | Trusted RPC assertion живёт не более 30 s, допустимый clock skew 5 s, transport mTLS | Проверить issuer/audience/service allowlist/actor/scope/version/expiry. Получатель не доверяет UserContext/legacy Header без валидного assertion. Persisted job не переиспользует просроченное assertion, а повторно получает право. |
| T07 | Cache обычных read permissions имеет hard TTL не более 30 s, без sliding expiry | Revocation event ускоряет eviction; mutation, secret issuance, download и dequeue требуют online authoritative recheck. Недоступный обязательный источник → 503. Ключи включают tenant/actor/channel/grant/version. |
| T08 | Доступность coverage вычисляется по UTC `[startAt,endAt)`; сохранённый anchor восстанавливает исходный день | Истёкший scheduler не даёт бесплатный grace. Month != 30 days. Табличные boundary vectors — [state-machines.md](state-machines.md#l05-invoice-деньги-и-календарь). |
| T09 | EUR/USD суммы — bigint minor units; FX decimal numeric(20,10), HALF_UP на выпуске invoice | Float/double для денег запрещены. Сохранять amount/currency/sourceRate/quotedAt/provider/sourceVersion. Новый счёт не переоценивает старый. Нет свежей разрешённой котировки → USD issuance disabled; EUR предлагается явным выбором. |
| T10 | Долговечный business operation ID — главный ключ повторов | HTTP key не заменяет уникальные invoice/receipt/period/refund keys в БД. Provider idempotency key выводится из server operation ID, никогда из email. UNKNOWN не повторяется новым payment intent. |
| T11 | Команда с внешним эффектом — durable operation + 202/status resource | Operation CAS/version/lease/fencing; retry same step. Внешний RPC/PSP/S3 не держит SQL transaction. Отказ до local commit не даёт outbox; неизвестный внешний исход требует reconciliation. |
| T12 | Финансовый журнал append-only; invoice snapshot и coverage — отдельные сущности | Не исправлять историю перезаписью amount/status payment. Counter-fact связан с original fact и evidence. Tenant deletion не превращается в финансовый CASCADE DELETE. |
| T13 | Входящий webhook ACK только после durable inbox; обработка асинхронна | Проверка подписи по raw bytes/merchant/env до записи нормализованного факта. Dedup event и dedup финансового эффекта раздельны; out-of-order и повторное eventId не дают второй period. |
| T14 | Банковское подтверждение требует операторской выписки и неизменяемой ссылки/hash evidence | Сохранять bank entry, payer, received time precision, confirmedBy/time. Скриншот клиента не факт; неоднозначная дата относительно deadline не угадывается. Хранилище evidence приватное, его содержимое не попадает в event/log. |
| T15 | Неизвестный плательщик/назначение → UNALLOCATED + WAITING_EVIDENCE | Изолированная очередь оператора с audit и точным ledger. Не активировать tenant по похожему email/сумме; возвращать только проверенному исходному плательщику, без произвольного нового IBAN из пользовательского сообщения. |
| T16 | Все ограничения — набор независимых reason codes, не один статус компании | Payment не снимает owner pause/platform block/dispute. Lifecycle, entitlement, role, grant, flags, quota — отдельные inputs общего capabilities evaluator. |
| T17 | Reservation expiry не освобождает место при неизвестном committed domain effect | Перед release проверить authoritative operation state; outage оставляет резерв и запускает retry. Lease и idempotency не заменяют друг друга. |
| T18 | Приватные download идут через authenticated streaming/range API | Клиент не получает reusable GET S3 URL, позволяющий обойти revoke. PUT presign ≤5 min, random server key, exact object HEAD перед commit. Размер аватара вне tenant storage. |
| T19 | Notifications разделяют TENANT и GLOBAL_IDENTITY scope | Обязательные финансовые/security inbox не исчезают из-за opt-out; routing и получатель актуальны на delivery. Не включать raw comment/body/secret в Kafka. Старый backlog чистого старта не replay. |
| T20 | Удаление account имеет admission fence в tenant-service | Оно блокирует гонку с назначением owner/last admin, затем auth tombstone и повторяемое revoke/cleanup. Удалённый автор выдаётся без старых PII snapshots. |
| T21 | Локальный audit сохраняет actor/channel/grant/tenant/operation/reason/version/effect | Логировать identifiers и result, не raw tokens, OTP, полные банковские выписки/секреты и приватный текст. Административные bypass всегда различимы. |
| T22 | Release checks и rehearsals реализуются как код/конфигурация | Manual sign-off — операционная процедура runbook; она не является задачей на аналитическое проектирование для разработчика. Отчёт имеет source SHA, environment, gate results; нет evidence → no-go. |
| T23 | Live коммерческий профиль — versioned server configuration с readiness guard | Stripe выбран D250, ES_V1 принят D253; неизвестные live merchant/tax/FX значения не получают фиктивные реквизиты. Fake provider разрешён в изолированном тестовом контуре; live actions требуют целостной конфигурации. |
| T24 | Технические лимиты фоновой обработки конфигурируются отдельно от тарифов | Bounded pages/chunks, per-tenant fair queues и concurrency; 429/Retry-After для admission overload. Не объявлять числа бизнес-SLO без измерений. Safety caps не дают дополнительных тарифных прав. |
| T25 | Банковский SLA WIRE_RETURN_ES_V1 использует versioned business calendar | 5 рабочих локальных дат Europe/Madrid, стартовая дата исключена; единый decision/send deadline. DST, timezone/calendar versions и hash snapshot фиксированы в C05, retries не сбрасывают срок. |
| T26 | Retention ES_V1 разделяет purpose archive и statutory blocking | Рабочие данные30d, backup35d, financial6y с исключениями, audit/logs и FREE marker по отдельным основаниям. Проверка holds перед irreversible шагом, restore применяет tombstones до traffic. |
| T27 | Финансовый документ после удаления выдаётся отдельным operator workflow | Проверенная личность/полномочия и конкретный document scope, короткая приватная доставка; deleted identity не восстанавливается, blocked profile не читается для поддержки. |

Протокольные enum/field names и номера protobuf определяются машинными [контрактами](contracts/README.md). Если реализации требуется изменить контракт, изменить DTO, schema, алгоритм и связанные Jira acceptance вместе; не добавлять скрытый endpoint с другой моделью прав.
