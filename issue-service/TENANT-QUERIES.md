# SQL-ядро поиска и доски — доступная часть TAS-344

`TenantIssueQueries` работает поверх нативного хранилища TAS-343. Это внутренний Java API,
а не активация публичных SearchIssues/ListIssuesForBoard. Нативные RPC поиска и доски
остаются закрыты транспортом; REST и legacy-профиль этим изменением не переключаются.

## Scope и согласованность

Для поиска вызывающий передаёт явный непустой набор до 100 различных проектов.
Текущая authority подтверждает каждый проект; результат проверяется на точное совпадение
набора и привязку permit к tenant/actor/action/project и сроку. Несовпадение или недоступность
не превращается в глобальный поиск, частичный ответ или пустой успешный результат.
Для поиска нужен action `searchIssues`, для доски — `listIssuesForBoard`.

Tenant и project predicates применяются в SQL до фильтров, count, window, сортировки и LIMIT.
Страница и total вычисляются одним statement в одном snapshot PostgreSQL. Пустая страница
за пределами диапазона сохраняет total. Удалённые задачи не входят ни в строки, ни в агрегаты.

Поддерживаются substring-поиск по ключу/summary/description и фильтры типа, статуса,
исполнителя, автора и приоритета. Значения параметризованы; `%`, `_` и `!` в тексте
экранируются как буквальные символы. Пустой текст не ограничивает поиск. Неизвестный
корректный ключ типа/статуса/пользователя даёт пустой scoped результат. Размер страницы 1–100;
смещение вычисляется в long. Поиск упорядочен по created_at/id по убыванию.

Доска читает один проект и один явный ключ типа. Ограничение 1–100 применяется отдельно
к каждой группе type/status. `statusTotal` считается до cursor и лимита, `hasMore` — по
оставшимся после cursor строкам колонки. Общий total не зависит от cursor.
Категории и допустимые статусы читает `PrimaryIssueAccess` через подписанный workflow RPC;
переданный клиентом список DONE не используется. Обычные колонки упорядочены по created_at/id
по возрастанию, DONE — updated_at/id по убыванию. Cursor разрешён только с явным статусом.
`doneSince` ограничивает только DONE. Время в SQL сравнивается с timestamptz.

После SQL повторно проверяется срок permit. Обязательный административный аудит выполняется
в той же транзакции; ошибка аудита или истечение permit не возвращает результат и откатывает
аудит. Business data, history, outbox, counters и idempotency при чтении не меняются.
Пакетный CountProjectIssuesBatchInternal дополнительно отвергает расширенный/неполный
набор разрешений от bulk authority.

Добавочная миграция `issue-query-indexes-0023` создаёт partial index для DONE cursor
(tenant/project/type/status/updated_at/id). Старые changesets не переписываются.

## Явная блокировка и оставшаяся работа

**Полная TAS-344 заблокирована TAS-321**: tenant-scoped directory и batch user details
ещё не готовы. Глобальное обогащение профилями и разрешающие заглушки не добавлены.
Снимки ядра содержат технические UUID без имён, email и аватаров.

После TAS-321 необходимо подключить безопасные batch enrichment и сборку публичных
SearchIssues/ListIssuesForBoard/detail responses, затем открыть соответствующие native
RPC и проверить REST → RPC → directory сквозным сценарием. Поиск без project_id требует
отдельного получения полного актуального доступного scope; этот API не заменяет его
ограниченным набором случайно выбранных проектов.

Фильтрация/обогащение метками, watchers/comments/attachment counts требуют соответствующих
нативных таблиц и контрактов соседних задач TAS-362/363/365. Merged-column ordering,
публичные page/cursor defaults и полная совместимость board response остаются работой
адаптера. Они не объявляются реализованными данным SQL-ядром. Пустые значения этих
публичных полей как успешная замена отсутствующим данным не публикуются.

Зависимый PR рассматривается относительно ветки TAS-343; слияние и развёртывание
не являются частью этой работы.

## Проверки

```sh
python3 scripts/harness.py check --module issue-service
```

`TenantIssueQueryIntegrationTest` использует настоящий PostgreSQL, shipped Liquibase,
app LOGIN и FORCE RLS с собственными A/B-фикстурами. Проверяются ограничения scope,
filters/count/window, обе сортировки cursor, пустые страницы, отзыв и истечение permit,
отказ аудита, отсутствие записей business data и план DONE index на данных двух компаний.
Проверка плана относится к scoped cursor SQL, а не к SLO или полной нагрузочной приёмке доски.
Эти тесты не доказывают готовность directory, публичного tenant REST или общего стенда.
